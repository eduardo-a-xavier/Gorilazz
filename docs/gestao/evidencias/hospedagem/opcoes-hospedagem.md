## GitHub Pages: limites oficiais relevantes

- **Fato:** site implantado no máximo 1 GB; deploy pode expirar em 10 minutos; soft bandwidth de 100 GB/mês; limite soft de 10 builds/hora não se aplica a workflow customizado de GitHub Actions. Repositório fonte recomendado até 1 GB. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), trecho: “Published GitHub Pages sites may be no larger than 1 GB” e “soft bandwidth limit of 100 GB per month”.
- **Fato:** Pages não é permitido como hospedagem grátis de negócio online/e-commerce/SaaS e não deve lidar com transações sensíveis. Projeto acadêmico estático não parece enquadrar-se nisso, mas essa classificação é interpretação do uso informado. [Mesma política oficial](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

## Passos para publicar com GitHub Actions (informativo; não executado)

1. Em **Settings → Pages**, selecionar **Source: GitHub Actions**. [Configurar fonte](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
2. Criar workflow em `.github/workflows/` disparado por push na branch padrão e opcionalmente `workflow_dispatch`.
3. `actions/checkout`; se necessário, gerar site estático para pasta de saída; `actions/upload-pages-artifact` apontando para essa pasta; `actions/deploy-pages` no job de deploy.
4. Dar permissões mínimas `contents: read`, `pages: write`, `id-token: write`, declarar ambiente `github-pages` e encadear deploy após upload. A documentação atual mostra actions `checkout@v6`, `configure-pages@v5`, `upload-pages-artifact@v4`, `deploy-pages@v4`; verificar versões vigentes quando for configurar. [Custom workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [tutorial](https://docs.github.com/en/get-started/start-your-journey/deploying-your-website-automatically).
5. Para domínio próprio, configurar domínio nas configurações Pages e DNS; `CNAME` sozinho não configura o domínio. Habilitar HTTPS quando certificado estiver disponível. [Domínio customizado](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site).

## Recomendação (interpretação)

**Cloudflare Pages** parece o melhor encaixe se o requisito prioritário for servir GLBs com controle de headers e rede CDN: suporta GitHub push deploy, headers `_headers`, TLS/domínio e arquivo individual até 25 MiB; o tamanho total informado de assets não viola o limite por si só. Antes de escolher, conferir o maior GLB individual e validar `Content-Type`, `Content-Encoding`, cache e carregamento real. O limite de transferência mensal de Pages não ficou confirmado nas fontes abertas nesta pesquisa, portanto não o rotulo como ilimitado.

**GitHub Pages** é recomendação mais simples quando a prioridade é fluxo direto no GitHub Actions e banda estimada cabe no limite soft de 100 GB/mês; tem limite claro de site total 1 GB, mas menor controle de headers específicos. Como a Engenharia já prepara Pages, permanecer nele é razoável para entrega de 30/11; registrar tráfego esperado e validar binário pelo endpoint publicado.

Netlify e Vercel também servem site estático, integram com GitHub e suportam headers/HTTPS; não há vantagem comprovada suficiente para migração antes do prazo sem medição. Antes de fixar escolha: obter tamanho individual dos GLBs, volume de visitas e consumo médio por visita; confirmar na resposta HTTP real se `.glb` é comprimido. Conteúdo GLB já otimizado pode não se beneficiar de gzip/Brotli adicional.
